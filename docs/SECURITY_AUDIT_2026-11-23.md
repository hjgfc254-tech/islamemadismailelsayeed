# Security audit — 2026-11-23

Scope: the full product cycle on the Firebase path (`functions/src/service.js` → `plan.js` → `runtime.js` → `services/*.js`
domain), Firestore / RTDB rules, hosting config, and the client render paths that were spot-checked.
Earlier rounds (H1, M1, M2, L1–L3 in `tests/unit/security-fixes.test.js`) were re-checked and still hold.
Nothing was deployed and production was not contacted.

## Cycle walk notes

- **Gate** (`service.api`): app, method, path (`..` refused, 300 characters) and the body size (100 KB, 200 KB for photos, 410 KB for admin media) are validated. Idempotency keys are scoped to the uid. Writes are rate-limited per uid, and per IP when there is no token. The actor always comes from the verified token plus a database lookup; the role is never taken from the client. Admin routes require the 8-digit code to be unlocked (scrypt hash, 5 failures lock the account for 15 minutes, counted inside a transaction).
- **Sign-up**: phone OTP, email and quick accounts behave as before. H1 (the verified phone owner takes the number back) still holds. Email and quick accounts cannot change their contact number. Phone accounts cannot switch to a different number (this audit also normalises the stored format).
- **New request**: required fields, a 2,000-character description and a geo range are validated. Open requests are capped at 3 for unverified and 10 for verified accounts (M1). Promo codes have expiry, use count, first-request-only and once-per-customer checks. Packages must be active.
- **Offers and assignment**: `selfDeal` blocks a provider from serving or bidding on a request from their own phone. Bids are capped by `priceCap` / `inspectionCap`, and the customer sees only totals (`customerRequestView` / `customerQuote`). Choosing one offer withdraws the others.
- **Contact data**: providers get phone, address, geo, liveGeo and chat only after acceptance, in the sync (`scopeFor`) and in API answers (`redactForProvider`). The PIN never reaches the provider.
- **Arrival PIN, chat, completion, cash, tip, review**: stars are integers 1–5, once per job. Tips are 5–1000, once per job. Chat messages are up to 500 characters, with the other side only after acceptance. Cash confirmations are by role, and a mismatch opens a complaint. See S3 and S5.
- **Admin**: content and AI routes are owner or admin only. Workforce and RBAC changes go through `workforce.handle`. The tech, content and finance roles get scrubbed data (`scrubForRole`, `roleView`). Delta sync (`since`) is admin-only and bounded (at most 6 hours old, never in the future). Alerts, tickets and digests require an unlocked admin and are rate-limited.
- **Rules**: Firestore denies every client read and write (all access goes through Functions). In RTDB, `signals/{uid}` is readable only by its owner and writable by no client, and `public/content` is read-only. See S6 for `typing`.
- **Input**: request, slide and notification text is escaped in the spot-checked render paths. Site content ids are restricted to `^[a-z0-9-]{2,24}$`, and images must be base64 `data:image/(webp|jpeg|png)`. No prototype-pollution sink was found: request bodies go only through object spread or allow-listed picks, and `Object.assign` receives only server-built patches. CSV export neutralises formulas (L1).
- **Secrets**: no private keys or API tokens in tracked files. The Firebase web key in `services/firebase-config.js` is public by design. `functions/.env` was not opened.
- **Not covered in depth**: a full XSS sweep of every `innerHTML` in the three apps (only spot checks), and the e2e/emulator runs (not run in this audit).
