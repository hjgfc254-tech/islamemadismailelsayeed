# P1 — Provider Interface Audit (فحص فقط — لم يُعدَّل أي كود)

## 1. ما هو موجود فعلًا
- **الملف:** `portal.js` (658 سطر) يحوي بوابة الفني **ولوحة الإدارة معًا** (الإدارة خارج النطاق — لا تُمس).
- **بوابة الفني = شاشة واحدة** `screens.provider` (portal.js:137): اختيار مزود تجريبي ← 9 بطاقات إحصاء ← زر التوفر ← 6 تبويبات فرعية (جديدة/مقبولة/جارية/عرض سعر/مكتملة/ملغاة) ← بطاقات `provCard`.
- **الحالة:** `PV = {tab}`، الدخول `store provId`، التجميع عبر `providerGroupOf(r,a)` (يربط حالة الطلب + حالة التكليف `assignments` بمجموعة المزود).
- **الإجراءات** (`data-pa`): login/logout/register/tab/avail/accept/reject/confirm/propose/enroute/started/arrived/sendQuote/finish.
- **دورة الطلب** (`market.js › FLOW`): received → searching → sent → accepted → scheduled → enroute → arrived → started → quote → completed → closed، + بديلتان `cancelled`/`failed`. التكليف: offered/accepted/rejected/withdrawn.
- **البيانات** (`MP`): providers (7 بذور demo)، assignments، transactions (value/commission/net)، reviews، notifications (`notesFor(to)`)، `rating()`، `acceptRate()`، `rateFor()`.

## 2. فجوات مقابل Provider Workspace 2.0
| المطلوب | الحالة |

| P3 لوحة رئيسية (تحية، توفر، «ماذا تفعل الآن؟»، مواعيد قادمة، تنبيهات) | جزئي: إحصاءات وتوفر فقط؛ لا تحية ولا «ماذا تفعل الآن» ولا مواعيد |

## 3. مخاطر وقواعد البرومبت
1. **شارة «معتمد»** تظهر من `status==='approved'` (portal.js:146, 271) والبذور تكتب «كهربائي معتمد» في `bio` — تخالف «لا شارة اعتماد دون بيانات موثوقة». يلزم تحويلها إلى «مقبول في المنصة (تجريبي)».
2. **تقييمات/أعداد أعمال** في البذور (4.8 / 342 …) مختلقة وإن وُسمت demo — يجب إظهارها كتجريبية أو إخفاؤها (البرومبت: لا تخترع تقييمات).
3. **ملف واحد للفني والإدارة:** أي إعادة هيكلة تخاطر بلوحة الإدارة. الحل: ملفات جديدة للفني (`provider-*.js`) وتبقى `screens.provider` موجّهة لها دون لمس `screens.admin`.
4. نمط `rerender` الشامل (يعيد رسم الشاشة كلها) — يُبقى؛ لا بنية جديدة.
5. `ROLE` + `body.role-mode`: بوابة الفني تظهر بلا شريط تبويب؛ التنقل الداخلي سيحتاج شريطًا سفليًا خاصًا (P2).

## 4. توصية بنية (لـ P2–P9)
- ملفات جديدة: `provider-ui.js` (مكوّنات/شريط تنقل)، ثم وحدات صغيرة لكل مرحلة؛ البيانات عبر `MP` فقط (إضافة حقول اختيارية لـ providers: `schedule`, `timeOff`, `certs`, `works` بدل جداول جديدة).
- إعادة استخدام `UIK` (حالات فارغة/تحميل/حوار تأكيد) و`providerGroupOf`.
