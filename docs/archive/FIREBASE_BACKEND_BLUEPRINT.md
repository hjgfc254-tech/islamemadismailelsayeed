# HANSALEHLAK — Firebase backend architecture blueprint (v1, 2026-11-14)

**Status:** a design document only. No application code, Firebase project, SDK or configuration has been added.

**Grounded in:**
- the existing adapter boundary: `services/*-api.js` and `docs/API_CONTRACTS.md`, which define the route table, the
  envelope, the actors and the business rules;
- the local read model `MP` (`services/local-market-store.js`);
- Admin RBAC (`apps/admin/rbac-store.js`).

**Principle:** the frontend keeps calling `HSApiClient.request(method, path, body)`. Only the transport changes.

## 1. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | **Firestore is a read model; every write goes through Cloud Functions** (callable functions, 2nd gen). Client writes are denied in the security rules. The only exception is a notification read-marker, and even that goes through a function in v1. | All business rules (the lifecycle, quotes, commission) currently run in the browser and must move server-side. One write path makes the rules auditable. |
| D2 | **Firebase Auth:** phone OTP for customers and providers; email/password with TOTP MFA for admins. | Matches the Egyptian phone-first UX. Admins need stronger authentication. |
| D3 | **Roles live in custom claims**: `{ role:'customer'\|'provider'\|'admin', pst:'approved'\|…, adm:'owner'\|'admin'\|'support'\|'finance'\|'moderator', pv:<permVersion> }`. They are set only by functions. | Rules and functions can authorize without extra reads. The provider role is granted **only on approval**, as in the current contract. |
| D4 | **Region `europe-west1`** for Firestore, Functions and Storage, in one region. | The lowest-latency mature region for Egypt with the full product set. Revisit `me-central2` if data residency requires it. |
| D5 | **App Check** (reCAPTCHA Enterprise on the web) is enforced on functions and Storage. | Bot and abuse protection for OTP, request creation and uploads. |
| D6 | **Cloud Storage** holds attachments and provider documents. Uploads go through signed paths; downloads are short-lived. | Replaces `services/local-attachments.js`. |
| D7 | **FCM** for push notifications. The inbox documents remain the source of truth. | Replaces the in-app-only notifications. |
| D8 | `backend/` (Express scaffolding) and `database/` stay untouched. Their module split (orders, quotes, finance…) is reused as the Functions code layout. | Respects the "preserve scaffolding" rule. No parallel server. |

## 2. Topology
```
Browser (vanilla apps) ──HSApiClient──► firebase-transport ──httpsCallable──► Cloud Functions (api.*)
        │                                                                          │  Firestore transactions
        │◄──────── onSnapshot (read-only, rules-filtered) ──── Firestore ◄─────────┤  audit log
        │◄──────── FCM push ◄── triggers (onDocumentWritten) ──────────────────────┤  counters
        └──────── Storage (uploads via callable-issued paths) ◄───────────────────┘
Auth (phone OTP / email+MFA) → custom claims set by functions: onboarding, approval, workforce
```

## 3. Data model (Firestore)
The model mirrors the `MP` entities. Ids are generated by Firestore unless noted. All timestamps are server timestamps.

| Path | Fields (main) | Notes |
|---|---|---|
| `customers/{uid}` | name, phone, status (`active`\|`suspended`), createdAt | uid = Auth uid |
| `customers/{uid}/addresses/{id}` | label, gov, area, addr, detail, type, isDefault | |
| `customers/{uid}/favorites/{kind_refId}` | kind (`provider`\|`service`), refId, at | The deterministic id makes the toggle idempotent |
| `providers/{uid}` | **public profile:** name, type, cats[], govs[], areas[], years, bio, rating, ratingCount, jobs, available, status | Readable by anyone only when `status=='approved'` |
| `providers/{uid}/private/profile` | phone, docs[] (Storage paths), specialRate, adminNotes | Only the owner and admins can read it. It holds the fields the public catalogue must never return. |
| `requests/{id}` | no (`HS-YYYY-NNNN`), customerId, providerId?, cat, item, problem, answers{}, desc, address{snapshot}, schedule{proposedAt, confirmedAt}, status, agreedValue?, finalValue?, free{reason,state}?, offeredTo[], createdAt, updatedAt | `status` follows the state machine in §6 |
| `requests/{id}/quotes/{qid}` | providerId, labor, parts, visitFee, discount, total (>0), state (`pending`\|`approved`\|`rejected`\|`superseded`), reason? | At most one `pending` quote |
| `requests/{id}/events/{eid}` | type, from, to, actor{uid,role}, at, meta | Replaces `history[]`; append-only |
| `requests/{id}/attachments/{aid}` | storagePath, mime, size, uploadedBy, scan (`pending`\|`clean`\|`blocked`) | |
| `transactions/{id}` | reqId, providerId, value, commissionRate, commission, deductions, free, collection (`pending`\|`collected`\|`waived`\|`none`) | Exactly one per completed request (the function enforces it with a `txn` lock field on the request) |
| `reviews/{reqId}` | providerId, customerId, stars 1–5, comment, at | id = reqId, so one review per request |
| `complaints/{id}` | byUid, byRole, reqId?, kind, text, status, resolution?, resolvedBy? | |
| `users/{uid}/notifications/{nid}` | title, body, link, readAt? | Per-actor inbox |
| `catalog/{version}/categories\|items\|problems\|questions` | The current `CAT` data | Read-only. Published by admins through a function. `catalog/current` points at the active version. |
| `settings/commission` | defaultRate, rates{cat:rate}, collectionModel, autoAssign, customerFee | |
| `admin/rbac/roles/{roleId}`, `admin/rbac/employees/{uid}` | permissions[], system; role, status | Mirrors `rbac-store.js`. The last-active-owner rule is enforced in the function. |
| `audit/{id}` | actor, action, target, before?, after?, at, ip? | Written only by functions |
| `counters/requests-{YYYY}` | next | Incremented in a transaction to produce the request number |

| Collection | Fields |

## 4. Security rules (skeleton)
```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    function signedIn() { return request.auth != null; }
    function role() { return request.auth.token.role; }
    function isAdmin() { return signedIn() && role() == 'admin'; }
    function isApprovedProvider() { return signedIn() && role() == 'provider' && request.auth.token.pst == 'approved'; }

    match /{document=**} { allow write: if false; }            // D1: every write goes through Cloud Functions

    match /customers/{uid} { allow read: if signedIn() && (request.auth.uid == uid || isAdmin());
      match /{sub=**} { allow read: if signedIn() && (request.auth.uid == uid || isAdmin()); } }
    match /providers/{uid} { allow read: if resource.data.status == 'approved' || (signedIn() && (request.auth.uid == uid || isAdmin()));
      match /private/{d} { allow read: if signedIn() && (request.auth.uid == uid || isAdmin()); } }
    match /requests/{id} {
      allow read: if signedIn() && (resource.data.customerId == request.auth.uid
                  || (isApprovedProvider() && (resource.data.providerId == request.auth.uid || request.auth.uid in resource.data.offeredTo))
                  || isAdmin());
      match /{sub=**} { allow read: if signedIn() && (get(/databases/$(db)/documents/requests/$(id)).data.customerId == request.auth.uid
                  || get(/databases/$(db)/documents/requests/$(id)).data.providerId == request.auth.uid || isAdmin()); } }
    match /users/{uid}/notifications/{n} { allow read: if signedIn() && request.auth.uid == uid; }
    match /reviews/{r} { allow read: if true; }
    match /catalog/{doc=**} { allow read: if true; }
    match /transactions/{t} { allow read: if isAdmin() || (isApprovedProvider() && resource.data.providerId == request.auth.uid); }
    match /complaints/{c} { allow read: if isAdmin() || (signedIn() && resource.data.byUid == request.auth.uid); }
    match /settings/{s} { allow read: if isAdmin(); }
    match /admin/{doc=**} { allow read: if isAdmin(); }
    match /audit/{a} { allow read: if isAdmin() && request.auth.token.adm in ['owner','admin']; }
  }
}
```
- Fine-grained admin module permissions (`HSAdminPermissionGuard` keys) are enforced in the functions, not the rules.
- An "offered" provider sees only the public request fields. The function returns a projection that hides the customer
  phone until acceptance.

**Storage rules:**
- `requests/{id}/attachments/{file}`: writable only by a path issued by `api.uploads.begin` (custom metadata `uploadToken`), ≤ 10 MB, `image/*` or `application/pdf`.
- `providers/{uid}/docs/{file}`: the owner may write it; only the owner and admins may read it.
- No public reads.

## 5. Cloud Functions (one callable per existing route)
Every function does five things:
1. verifies Auth and App Check;
2. reads the claims;
3. validates input (a shared schema, the same rules as the adapters);
4. runs a Firestore **transaction**;
5. writes `events` and `audit`, and returns the **existing envelope** (`{ok,status,data}` / `{ok:false,status,error}`).

Error mapping:

| Envelope code | `HttpsError` code |
|---|---|
| 400 | `invalid-argument` |
| 401 | `unauthenticated` |
| 403 | `permission-denied` |
| 404 | `not-found` |
| 409 | `failed-precondition` |
| 422 | `invalid-argument`, with `details` |
| 503 | `unavailable` |

| Function | Route(s) (from `API_CONTRACTS.md`) |
|---|---|
| `auth.me`, `auth.onboardCustomer` | `GET /auth/me`; first sign-in creates `customers/{uid}`, claim `role=customer` |
| `requests.create/list/get/cancel/pickProvider` | `POST/GET /requests…`, `/cancel`, `/provider` |
| `requests.respond/schedule/advance/complete/close/review` | Provider and customer lifecycle routes |
| `quotes.submit/approve/reject`, `free.propose/respond/complete`, `free.reasons` | Quote and free-service routes |
| `catalog.*` | Served by direct Firestore reads (public). No function is needed except `catalog.publish` (admin). |
| `providers.register/me/update/availability` | `register` creates a `pending` provider and no role claim |
| `customers.me/addresses.*/favorites.toggle` | Customer routes |
| `notifications.list/markRead` | Inbox |
| `complaints.create/list/resolve` | Support |
| `finance.earnings/transactions/setCollection/commission.get/set` | Finance (`adm` ∈ owner, finance) |
| `admin.summary/providers.list/providers.setStatus/providers.setRate/requests.candidates/requests.assign/customers.*` | `providers.setStatus('approved')` sets the claim `role=provider, pst=approved` and revokes refresh tokens |
| `workforce.*`, `rbac.*` | Employees and roles. The last-active-owner rule applies; claims `role=admin, adm=<role>`. |
| `uploads.begin/finish` | Issues the Storage path and token; `finish` records the attachment and queues the scan |

**Triggers:**
- `onRequestWritten`: fans out notifications (inbox + FCM) and updates the provider `jobs` count.
- `onReviewCreated`: recomputes `rating` and `ratingCount`.
- `onAttachmentFinalized`: runs the malware/type scan and sets `scan`.
- Scheduled `autoAssign` (every 2 minutes, when `settings.autoAssign` is on): offers `searching` requests to matching providers.
- Scheduled `staleRequests`: alerts admins (as the dashboard's "3 requests without a provider for more than 24 hours" does).

## 6. Request state machine (server-enforced; identical to the current contract)
| From | Action (actor) | To | Guards |
|---|---|---|---|
| received/searching | offer (system/admin) | sent | provider approved, available, covers cat + gov |
| sent | respond accept (provider) | accepted | provider in `offeredTo` |
| sent | respond decline (provider) | searching | |
| accepted | schedule confirm (either side) | scheduled | `proposedAt` exists |
| scheduled → enroute → arrived → started | advance (provider) | next | Only these three targets |
| started | quotes.submit (provider) | quote | total > 0; the previous pending quote becomes `superseded` |
| quote | approve (customer) | started | Sets `agreedValue`. It does **not** complete the job. |
| quote | reject (customer) | started | Reason recorded |
| started | complete (provider) | completed | No pending quote; value equals `agreedValue`, or > 0 when there is no quote. Creates exactly 1 transaction. |
| completed | close (customer) | closed | Unlocks one review |
| started | free.propose → respond(accept) → free.complete | completed | value 0, transaction `free:true, collection:'none'` |
| before `started` | cancel (customer/admin) | cancelled | |

Commission = `providers/{uid}/private.specialRate ?? settings.rates[cat] ?? settings.defaultRate`, computed only in
`complete`.

## 7. Frontend integration plan (no app code changed yet)
1. **SDK delivery:** vendor the Firebase modular SDK (app, auth, firestore, functions, storage, messaging, app-check) as
   ESM files under `assets/vendor/firebase/<version>/`. They are loaded by one module, `services/firebase-bootstrap.js`,
   which exposes `globalThis.HSFirebase`. This keeps the classic-script architecture with no bundler. **The new
   dependency needs owner approval.**
2. **`services/firebase-transport.js`:** maps `METHOD /path` to a function name using the route table, calls
   `httpsCallable`, and normalizes the result to the envelope. `HSApiClient` selects the transport through
   `shared/config/app-config.js` (`transport: 'mock' | 'firebase'`). The mock stays as the default and for tests.
3. **`auth-api.js`:** the actor comes from `onAuthStateChanged` and `getIdTokenResult().claims`. The three demo session
   modules (`HSCustomerSession`, the Provider demo picker, the Admin roster picker) remain only in mock mode.
4. **Read model:** `MP` becomes a cache filled by `onSnapshot` listeners scoped by role (own requests, own inbox,
   offered/assigned jobs, and for admins, paged queries). `realtime-client.js` re-emits snapshot changes on its existing
   event names, so screens do not change.
5. **Uploads:** `uploads-api.js` / `local-attachments.js` switch to `uploads.begin` → `uploadBytesResumable` → `uploads.finish`.
6. **Service worker:** never cache `*.googleapis.com`, `*.cloudfunctions.net` or Firestore channels (network-only).
   Bump `CACHE`.
7. **CSP:** allow `apis.google.com`, `*.googleapis.com`, `*.firebaseio.com`, `*.cloudfunctions.net` and the reCAPTCHA
   origins. Move the inline intro pre-check into a file.

## 8. Environments, testing, migration
- **Projects:** `hansalehlak-dev`, `-staging` and `-prod`. Each web app's config is injected per environment into
  `app-config.js`; the API keys are public by design, and App Check protects them.
- **Emulator Suite** (Auth, Firestore, Functions, Storage) backs three test layers:
  - rules unit tests (`@firebase/rules-unit-testing`) for every row of §4;
  - a function test per state-machine row in §6, reusing the cases from `tests/unit/order-lifecycle.test.js` and
    `api-adapters.test.js`;
  - the existing CDP runners against the emulator with `transport:'firebase'`.
- **Seed and migration:**
  - a one-off admin script loads the `CAT` catalogue as `catalog/v1`, plus the commission settings and the RBAC roles;
  - the demo `MP` data is **not** migrated to production. It seeds dev and staging only.
- **Observability:** structured logs per function (`reqId`, actor, action, latency), alerting on 5xx rates and
  OTP-abuse spikes, and a BigQuery export of `audit`.

## 9. Delivery phases
| Phase | Scope | Exit criteria |
|---|---|---|
| F0 | Projects, App Check, emulators, rules and indexes in the repository (`firebase/` folder) | Rules tests green |
| F1 | Auth + `auth.me` + customer onboarding; `firebase-transport` behind the flag | Customer signs in with OTP on staging |
| F2 | Catalogue reads, provider registration and approval (claims), provider profile | Admin approves a provider, who gains the role |
| F3 | Request lifecycle + quotes + free service + transactions (§6) | Every lifecycle test passes against the emulator |
| F4 | Notifications (inbox + FCM), realtime snapshots, uploads + scanning | Customer, Provider and Admin runners pass on staging |
| F5 | Admin finance, RBAC/workforce, audit, reports; CSP, SW and abuse limits | Security review; load test on request creation |
