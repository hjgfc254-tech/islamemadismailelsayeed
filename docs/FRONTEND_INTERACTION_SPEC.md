# FRONTEND INTERACTION & UI STATE SPECIFICATION

## 1. صيغة توثيق التفاعل
لكل عنصر تفاعلي سجل: ID، الصفحة، العنصر، trigger، شروط التفعيل، state قبل/بعد، النتيجة المرئية، feedback، الإلغاء/التراجع، keyboard behavior، وحالة التنفيذ.

**الصيغة:** `Trigger → Guard → State transition → Visible feedback → Recovery`.

## 2. الحالات العامة
| الحالة | ما يجب أن يراه المستخدم | قاعدة التنفيذ |
|---|---|---|
| Initial | هيكل مفهوم أو محتوى أولي | لا تترك منطقة فارغة بلا تفسير |
| Loading | مؤشر/ skeleton ورسالة عند طول الانتظار | لا تكرر المؤشر في كل عنصر بلا داعٍ |
| Empty | سبب عدم وجود محتوى وخطوة تالية | فرّق بين لا توجد بيانات ولا توجد نتائج للفلتر |
| Error | وصف مفهوم وخيار تصحيح/إعادة محاولة | لا تعرض stack trace |
| Success | تأكيد دقيق لما تم محليًا | لا توحِ بإرسال خارجي |
| Disabled | مظهر غير نشط وسبب عند الحاجة | لا تجعل العنصر يبدو قابلًا للتفعيل |
| Offline | بيان ما يعمل محليًا وما يتطلب اتصالًا | لا تعد بمزامنة غير منفذة |
| Focus | مؤشر واضح عند التنقل بلوحة المفاتيح | لا تزل outline دون بديل |

## 3. التنقل
- كل رابط يذهب إلى وجهة موجودة وصحيحة.
- كل إجراء داخل الصفحة يستخدم button، وكل انتقال يستخدم link/route semantics.
- عند الانتقال لصفحة جديدة، حدد هل scroll يعود للأعلى وهل تحفظ حالة الفلاتر/المسودة.
- عند دعم history، اختبر back/forward وإعادة التحميل.
- لا تعرض route في navigation قبل وجود وجهة قابلة للاستخدام؛ يمكن عرضه كـ coming soon بوضوح.

## 4. البحث والفلاتر
- وضح هل البحث فوري أم بعد submit.
- حدد normalization للغة العربية إذا كان موجودًا بالفعل؛ لا تدّع دعمًا غير منفذ.
- أظهر query الحالي ووسيلة مسح.
- اعرض عدد النتائج أو حالة عدم وجود نتائج عند توفره.
- وضح هل الفلاتر additive أم mutually exclusive، وكيفية reset.
- اختبر تفاعل البحث مع الفلاتر والفرز معًا.

## 5. النماذج والمعالجات متعددة الخطوات
- حدد ترتيب الخطوات وشروط السماح بالانتقال.
- حافظ على إدخالات المستخدم عند الرجوع.
- تحقق من الحقول على مستوى الحقل وعند الإرسال النهائي.
- وضح حفظ المسودة ومتى يتم استعادتها/مسحها.
- المرفقات: أنواع وأحجام مسموحة، progress، فشل، إزالة، معاينة، وحدود التخزين المحلي.
- منع النقر المزدوج وإظهار حالة submit.

## 6. Dialogs, drawers and menus
- وثق سبب الفتح ومصدره.
- إغلاق بالنقر خارج النافذة فقط إذا لم يسبب فقد بيانات غير مقصود.
- إغلاق Escape عند الأمان، وإرجاع focus للمشغل.
- على الهاتف يجب ألا يغطي زر الإغلاق أو المحتوى الأساسي.
- القوائم تدعم لوحة المفاتيح ولا تعتمد على hover.

## 7. Tables and data lists
- loading/empty/error states واضحة.
- فرز الأعمدة يوضح الاتجاه الحالي.
- فلاتر نشطة قابلة للمراجعة والمسح.
- على الهاتف: حدد هل تتحول البطاقات أو يسمح بتمرير أفقي مع تلميح واضح.
- لا تخفِ أعمدة أو إجراءات مهمة بصمت.

## 8. UI interaction inventory
يجب أن تتضمن مراجعة كل صفحة قائمة بجميع: links, buttons, inputs, selects, checkboxes, tabs, menus, dialogs, accordions, pagination, sortable headers, file inputs. كل عنصر يجب أن يكون له expected outcome أو سبب disabled.

## 9. Feedback copy
اكتب رسائل قصيرة تحدد ما حدث وما الخطوة التالية. تجنب «حدث خطأ» وحدها عندما يمكن توضيح الحقل أو الإجراء. لا تستخدم «تم الإرسال بنجاح» لعملية محاكاة خارجية؛ استخدم «تم حفظ النموذج محليًا للتجربة» عند انطباق ذلك.
